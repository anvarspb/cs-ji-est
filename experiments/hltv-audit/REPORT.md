# Техническая проверка gigobyte/HLTV для CS PULSE

Дата: 14 ноября 2026. Проверяемый пакет: **npm `hltv@3.5.0`**, зафиксирован отдельным `pnpm-lock.yaml`. Node.js **24.22.1**, TypeScript **5.9.3**. Основной сайт не изменён: SHA-256 30 файлов исходников и конфигурации сверяются с `site-before.json`.

## Границы проверки

Тестируются реальные экспортируемые методы установленной библиотеки, а не их переписанные имитации. Страницы подставляются через `new Hltv({ loadPage })` из локальных HTML-образцов. До импорта пакета блокируются HTTP/HTTPS, сокеты, TLS, DNS, HTTP/2, UDP, fetch и WebSocket. Любая попытка сетевого обращения приводит к ошибке; после каждого теста проверяется отсутствие таких попыток. Неизвестный маршрут образца отклоняется, пагинация ограничена числом локальных вызовов.

**Все образцы синтетические.** Они описывают селекторы библиотеки и контролируемые изменения: версии рейтинга, отсутствующие поля, изменённые классы и performance-график. Они не скачаны с HLTV и не доказывают работоспособность на текущем live DOM. Реальный доступ к HLTV, сбор матчей, Cloudflare/CAPTCHA bypass не запускались. Подготовка использовала npm registry и исходники GitHub.

## Совместимость

| Проверка | Результат |
| --- | --- |
| Импорт и работа методов на Node 24.22.1 через `Hltv` / `HLTV` | Работает локально |
| Чистый Node ESM: `import HLTV from 'hltv'` | Default — CommonJS-обёртка; `.getMatches` отсутствует |
| TypeScript 5.9.3, NodeNext, `strict`, `skipLibCheck: false` | Ошибка TS2724 в двух местах `scraper.d.ts`: отсутствует `cheerio.Root` |
| NodeNext, именованные импорты, `skipLibCheck: true` | Проходит |
| ESNext/Bundler, `skipLibCheck: true`, как подход проекта | Проходит, включая default-import на уровне типов |
| NodeNext с default-import и обращением к `.getMatches` | TS2339; компилятор обнаруживает CommonJS-обёртку |

Прохождение Bundler typecheck не является проверкой реальной Next.js-сборки с библиотекой. Основной сайт намеренно не пересобирался и не менялся. Для интеграции предпочтителен именованный `Hltv` с внедряемым загрузчиком; пакет должен оставаться только на сервере в Node.js runtime.

Важно: npm-релиз и GitHub master — разные артефакты. В установленном релизе зависимости: `cheerio 1.0.0-rc.12`, `got-scraping 3.2.15`, `socket.io-client 2.4.0`. Текущий просмотренный master указывает другие версии. Результаты этой проверки относятся именно к зафиксированному npm-релизу.

## Методы

| Метод | Подтверждено на образцах | Выявленные ограничения |
| --- | --- | --- |
| `getMatches` | 1 локальная загрузка; команды и ID, время, формат, событие, LIVE; фильтры сериализуются в URL | Событие сопоставляется по имени с отдельным списком; при отсутствии списка теряется event. Изменение класса карточки теряет матч. ` LIVE ` не распознаётся. Произвольный HTML может выглядеть как корректный пустой список |
| `getResults` | Счёт, дата, BO3 и BO1/map; фильтры; пагинация до пустой страницы | Даже один результат требует второй загрузки пустой страницы. Нет встроенного maxPages. Нет ID команд и события в ответе. Разделитель `2 : 1` вместо `2 - 1` даёт NaN/undefined. Сокращение Anubis `anb` преобразуется в `default`, хотя `GameMap.Anubis` существует |
| `getMatch` | Команды, событие, BO3, победитель, карты, раунды, отдельные statsId/mapStatsId, явные статусы | Пустая страница вызывает TypeError из-за event href. Неизвестный текст статуса становится Scheduled. Пустые счёты карт корректно остаются без result |
| `getMatchStats` | Счёт серии, IDs, игроки обеих команд, K/D/A, ADR; **2** локальные загрузки | Сбой performance-графика уничтожает результат основного парсинга. Без event href возникает TypeError. Изменение классов таблиц даёт пустые массивы. Единственная таблица дублируется в обе команды |

`matchId`, `statsId`, `mapStatsId` не взаимозаменяемы: в образцах это 1000, 2000, 3000. Идентификатор из `getMatch().statsId` предназначен для `getMatchStats`. Источник не даёт оснований считать свою дату фактическим временем завершения: `finishedAt` нельзя подменять временем начала.

## K/D/A, ADR и Rating

- На ожидаемой разметке получены **58 K / 40 D / 12 A / 92.4 ADR**; flash assists читаются отдельно (3) и не должны повторно прибавляться к A.
- Отсутствующий ADR возвращается как `undefined`, что подходит для отображения «—» после нормализации.
- Отсутствующий K тоже возвращается как `undefined`, хотя тип библиотеки обещает `number`: одной проверки TypeScript недостаточно.
- Версия рейтинга в `title="Rating 3.0"` игнорируется: значение 1.32 оказывается в **rating1**.
- Если `.ratingDesc` содержит текст `1.0`, `2.0`, `2.1` или `3.0`, чтение всей `.st-rating` склеивает значение и подпись; в подготовленных образцах число становится `undefined`. Для `2.0` выбирается ключ `rating2`, но значение уже потеряно; прочие версии попадают в ветку `rating1`.
- Публичные типы содержат только `rating1` / `rating2`. Отсутствие `rating3` подтверждается отдельной compile-only проверкой с `@ts-expect-error`.
- Подмена старой строки графика `Impact rating` на `Round swing` воспроизводит TypeError. Это тест устойчивости, **не утверждение, что текущий HLTV DOM имеет именно такой вид**.

## Необходимые изменения перед интеграцией

1. Получить разрешённый источник и образцы реальных современных страниц/выгрузок. Без этого точный перечень новых CSS-селекторов и полноценную поддержку Rating 3.0 подтвердить нельзя. Условия HLTV запрещают scraping; открытая лицензия библиотеки не даёт прав на данные.
2. Исправить декларации `cheerio.Root` на актуальный контракт `CheerioAPI` с проверкой совместимости обёртки. `skipLibCheck` — временный способ скрыть ошибку деклараций, не исправление парсера. Закрепить версии зависимостей; отдельно тестировать обновления Cheerio.
3. Отделить разбор нужной таблицы от performance-графиков и остальных ненужных блоков; ошибка необязательного блока не должна терять K/D/A и ADR. Для MVP достаточно показателей за весь матч.
4. Читать числовой Rating отдельно от подписи, извлекать версию явно и хранить `{ value, version, source }`, а не считать `rating1` универсальным fallback. Неизвестную версию не угадывать; не рассчитывать «HLTV Rating» самостоятельно.
5. Добавить runtime-валидацию: конечные числа, целые неотрицательные K/D/A, IDs, событие, две разные команды и корректное распределение игроков. Неполную таблицу хранить как неполную, не дублировать и не подставлять нули.
6. Явно различать отсутствие данных, изменение схемы, отказ доступа и пустую корректную выборку. При защитной странице остановить обновление без обхода. Неизвестный статус считать неизвестным; `Deleted` не приравнивать автоматически к подтверждённой отмене. LIVE — только по свежему явному подтверждению; промежуточный счёт отбрасывать.
7. Ограничить страницы/вызовы и время обработки результатов; исправить карту Anubis и нормализацию форматов/счёта. Фильтры в URL не заменяют повторную проверку allowlist по ID на своей стороне.
8. В CS PULSE подключать только через серверный адаптер `data.ts`, с независимой моделью и последним корректным JSON-снимком на постоянном диске. Нужны source ID, nullable метрики, versioned Rating и время обновления. Ошибочный ответ не заменяет последний снимок. Таблицы и карты показываются только после подтверждённого завершения.

## Запуск и результаты

Из каталога `experiments/hltv-audit`:

```powershell
pnpm install --frozen-lockfile --node-linker=hoisted --store-dir .pnpm-store
node scripts/run-audit.mjs
```

Runner использует только локальные исполняемые файлы и сохраняет `results/summary.json` и подробные журналы. **39 parser-тестов проходят**: часть проверяет корректную работу, часть намеренно фиксирует воспроизводимые дефекты исходной библиотеки. Зелёный статус не означает, что дефекты исправлены. Строгая компиляция и NodeNext default-import ожидаемо завершаются с ошибкой; runner проверяет именно ожидаемые коды и диагностику. Неожиданный результат любой проверки делает общий запуск неуспешным.

Для отдельного запуска парсеров: `node --test test/parsers.test.mjs`. Для строгой компиляции: `node node_modules/typescript/bin/tsc --project tsconfig.json` (ожидается ошибка). Для настроек Bundler: `node node_modules/typescript/bin/tsc --project tsconfig.bundler.json` (ожидается успех). Файлы `types/*.mts` предназначены только для компиляции и не должны исполняться.

Источники для сверки кода: [репозиторий](https://github.com/gigobyte/HLTV), [getMatches](https://github.com/gigobyte/HLTV/blob/master/src/endpoints/getMatches.ts), [getResults](https://github.com/gigobyte/HLTV/blob/master/src/endpoints/getResults.ts), [getMatch](https://github.com/gigobyte/HLTV/blob/master/src/endpoints/getMatch.ts), [getMatchStats](https://github.com/gigobyte/HLTV/blob/master/src/endpoints/getMatchStats.ts), [парсинг игроков](https://github.com/gigobyte/HLTV/blob/master/src/endpoints/getMatchMapStats.ts), [условия HLTV](https://www.hltv.org/terms). Воспроизводимые результаты относятся к установленным файлам `node_modules/hltv/lib`, а не к плавающей ветке master.
