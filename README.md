# CS PULSE — реальные данные Cito

Next.js App Router, TypeScript, Tailwind CSS, Lucide. Существующие маршруты `/`, `/results`, `/tournaments`, `/match/[id]` и Neon Glass сохранены. Рабочие страницы читают только общий JSON-снимок; `mock-data.ts` не используется.

## Локальный запуск

Node.js 24.22.1. `pnpm install --frozen-lockfile`, затем `pnpm dev` (или `npm run dev` при доступном npm). В текущем окружении можно напрямую: `node node_modules/next/dist/bin/next dev --webpack`.

Проверки: `node --test tests/*.test.mjs`, `node node_modules/typescript/bin/tsc --noEmit`, `node node_modules/next/dist/bin/next build --webpack`.

`.env.local` содержит `CITO_API_KEY`, только для обновляющего скрипта. Не коммитить и не помещать в `NEXT_PUBLIC_*`. Браузеру и Render для чтения публичного снимка ключ Cito не нужен. Начальный снимок в `deployment-data` получен из реальных ответов и содержит 20 уже учтённых запросов.

Ручное обновление: `node scripts/update-cito.mjs`. Состояние и снимок по умолчанию сохраняются в `.cito/data`, который исключён из Git. Это режим локальной разработки, а не постоянное облачное хранилище. Не запускайте локальный обновитель параллельно с Actions с тем же ключом: отдельные копии ledger не синхронизируются. /health дополнительно ограничивает расход текущего периода аккаунта.

## Публикация — GitHub и Render Free

1. Создайте публичный GitHub-репозиторий и загрузите проект в ветку `main`, исключив `.env.local`, `.cito`, `.next`, `node_modules`, `.pnpm-store`. Стандартные Actions в публичном репозитории бесплатны. Ключ никогда не вводится в файлы workflow.
2. Settings → Secrets and variables → Actions → New repository secret: **CITO_API_KEY**. Значение — ваш ключ.
3. Включите Actions. Workflow `Update Cito snapshot` уже подготовлен в `.github/workflows/cito-data.yml`. Разрешите workflow запись содержимого репозитория (contents: write); правила защиты ветки `data` должны разрешать запись github-actions.
4. Запустите workflow вручную (Actions → Update Cito snapshot → Run workflow). Он создаст отдельную ветку `data` из проверенного начального состояния. Дальше она хранит `state.json` (ledger/повторы) и `snapshot.json` (данные страниц). Не удаляйте ветку и не сбрасывайте её состояние: это сбросит локальный 30-дневный учёт!
5. Создайте Render **Web Service / Free**, подключив тот же репозиторий и **ветку main**, либо примените `render.yaml` как Blueprint. Build command: `npx --yes pnpm@11.25.0 install --frozen-lockfile && npx --yes pnpm@11.25.0 run build`. Start command: `npm run start -- --hostname 0.0.0.0 --port $PORT`. Node: 24.22.1.
6. В Environment Render добавьте **CITO_SNAPSHOT_URL** = `https://raw.githubusercontent.com/OWNER/REPO/data/snapshot.json` (замените OWNER/REPO). CITO_API_KEY в Render не нужен.
7. Render автоматически пересобирается только при изменениях main. Изменения data не запускают сборку. Страницы Next.js динамические, JSON читается во время работы с общим кешем на 60 секунд; возможна дополнительная задержка CDN GitHub.

Публикация и настройки аккаунтов не выполнены агентом: в текущей папке не было Git remote, GitHub/Render ещё нужно настроить владельцу. Важно не публиковать локальный `.env.local`.

## Автоматизация и хранение

Workflow запускается каждый час на 17-й минуте UTC, один писатель (`concurrency`, без отмены текущего запуска). Подготовка состояния использует git worktree. Установки npm и сборки сайта внутри обновления нет: используется стандартный Node.js.

- Один общий запрос расписания не чаще чем раз в 12 часов, `limit=100`. Период видимого расписания — 7 дней вперёд.
- Первый запуск также получает общие результаты для начального наполнения, если нет проверенного seed. Затем `/recent` вызывается один раз не чаще часа, когда есть отслеживаемые матчи, начавшиеся не менее часа назад. Один запрос сопоставляется со всеми матчами, независимо от их числа.
- Через 12 часов ожидания автоматический опрос конкретного неподтверждённого матча прекращается. Он не объявляется завершённым: показывается «Нет результата». Перенос времени при следующем расписании снимает остановку. Результат может быть обнаружен и позже в общем списке, пока матч хранится.
- После завершения загружаются карты и player-stats. Успешные данные больше не запрашиваются. Не более двух запросов деталей за запуск; до трёх попыток каждого ресурса, интервалы ожидания 2, 6, 24 часа. Частичные данные сохраняются сразу.
- K/D/A, ADR и Cito Rating показываются **по картам**. Никаких придуманных средних за серию. Отсутствующие значения — «—». Rating отображается только с подтверждённым `cito_rating_1`.
- В рабочем снимке хранятся результаты/статистика за 7 дней, расписание следующих 7 дней и нерешённые матчи не старше 7 дней. Jobs удаляются вместе с матчами, ledger сохраняет 30 дней. Это очистка текущих JSON: GitHub Git сохраняет историю прошлых коммитов, физическое стирание Git-истории не реализовано. Начальный проверенный seed в main не является обновляемым архивом; устаревшие записи из него не показываются.
- Таймеры браузера меняют подпись LIVE* по местному времени. Видимая вкладка раз в 5 минут и при возвращении на неё обновляет отображение сохранённого снимка через Next.js — без запросов данных к Cito. Это не заменяет планировщик. Через 12 часов LIVE* перестаёт показываться. Подтверждённый результат имеет приоритет.

## Квота и устойчивость

Жёсткий порог — **450 попыток за скользящие 30 дней**. Расход учитывается заранее: reservation записывается и в Actions коммитится/отправляется в data **до сетевого запроса**. При аварии возможен консервативный лишний учёт одной попытки, но запрос не теряется из ledger. При сбое git push Cito не вызывается. Фактические ошибки транспорта тоже занимают резерв. /health не расходует месячную квоту и дополнительно проверяет общий расход аккаунта; если health недоступен, обновление откладывается.

Перед каждым вызовом повторно проверяются лимиты. Нет автоматических транспортных повторов. Запросы разделены минимум 6.2 секунды. 429 соблюдает Retry-After и останавливает текущий цикл; 401/403 приостанавливают попытки на 12 часов. Предыдущие данные сохраняются. Другие ключи/приложения аккаунта делят квоту Cito: используйте выделенный ключ и не удаляйте ledger. Полной атомарности между сторонними приложениями и Cito нет.

Оценка: `60 + H + 2M + E + R`, где H — число часов общего опроса результатов, M — число новых завершённых матчей, E — запросы событий (сейчас **0**, берутся вложенные поля списков), R — ошибки/повторы и проверки. Например, 150 часов, 80 матчей и 20 дополнительных попыток = **390 запросов / 30 дней**. Для активности на весь день и большого количества матчей 450 не хватит: обновления остановятся, а не перейдут на платный тариф. Публикация/проверки уже использовали 20 запросов, они учтены в seed.

`/recent` ограничен 100 записями и в реальной проверке вернул hasNext=false при заполненном лимите. Поэтому нельзя обещать все результаты за 7 дней или обнаружение всех завершений в очень загруженные часы. Сайт явно показывает предупреждение; скрытой пагинации и дополнительных запросов нет. Аналогично, усечённое расписание не расширяется автоматически.

`config/competitions.json` — явные ID допущенных **изданий** турниров: BLAST Rivals 2026 Season 2 и PGL Major Singapore 2026 Stage 1 (подтверждены ответами). Новые значимые события нужно добавлять по ID в этот файл. Автодопуск по названию команды или полю tier API запрещён. Участники разрешённых событий допускаются все — квалификации отдельно не добавляются.

Если GitHub недоступен, процесс Render сохраняет последний корректный ответ в памяти; после холодного старта остаётся проверенный seed, пока источник не восстановится. Старые данные отсеиваются по 7-дневному окну при каждом чтении. При отсутствии данных — честное пустое состояние. При превышении суток с последнего обновления появляется предупреждение.

## Ограничения бесплатной схемы

Render Free засыпает после 15 минут без посетителей, холодный старт может занимать около минуты. Локальный диск Render непостоянен и не используется как основное хранилище. Внешние обновления Actions работают, пока Render спит. Actions может задерживать/пропускать запуски; в публичных репозиториях schedule отключается после 60 дней отсутствия активности. Проверяйте уведомления Actions. Бесплатные лимиты Render/Actions зависят от аккаунта; не подключайте платный тариф или расходы сверх бюджета.

Cito Free предназначен для тестирования/некоммерческого использования, детальные данные доступны за последние 30 дней. Наше окно 7 дней укладывается в него. Поставщик — независимый агрегатор без гарантии прав на сторонние материалы. Сайт не использует HLTV, демки, профили игроков или базу данных.

Реальная проверка: [docs/CITO-VERIFICATION.md](docs/CITO-VERIFICATION.md). Локальные тесты не обращаются к API. Официальные документы: [Cito](https://citoapi.com/docs/api/cs2/), [лимиты Cito](https://citoapi.com/docs/rate-limits/), [условия Cito](https://citoapi.com/terms/), [Render Free](https://render.com/docs/free), [Actions schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
